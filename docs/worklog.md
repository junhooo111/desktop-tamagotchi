## 2026-11-24 — 옆모습 전신·다양한 동작으로 개편

- 요청: 마우스 커서만 한 크기로 줄이고, 정면 대칭 대신 옆모습 전신에 픽셀 움직임을 넣는다. 졸기·자기, 뛰기, 걷기, 벽 타기, 미끄러지기, 마우스에 매달리기(10초 방치), 혼자 놀기.
- 그림 방식 변경: 문자열 격자를 손으로 찍는 대신 타원·사각형을 겹치고 윤곽선을 자동으로 두르는 코드(`pixel.ts`)로 그린다. 다리 위치만 바꿔 걷기·뛰기 프레임을 만들고, 벽 타기는 같은 그림을 뒤집고 90도 돌려서 쓴다.
- 크기: 한 칸 2배(알·새끼 32px), 3배(성체 48px). `layout.ts` 의 `STAGE_SCALE` 만 고치면 된다.
- 창은 펫보다 크게(160x120) 두어 말풍선·점프 자리를 확보하고, 창 위치를 펫 기준으로 계산해서 펫이 화면 가장자리까지 닿는다.
- 행동은 `behavior.ts` 상태 머신으로 분리: idle → 걷기/뛰기/졸기/놀기/벽 타기 중 하나. 졸다가 70%는 잠든다. 벽 타기는 가장자리로 걸어가 오르고, 초당 12% 확률로 미끄러진다.
- 매달리기: 마우스를 10초 가만히 두면 달려와 매달리고, 마우스가 6px 넘게 움직이면 떨어진다. 매달린 동안은 펫이 입력을 받지 않아 클릭이 그대로 통과한다. 알·자는 펫·벽 타는 펫은 오지 않는다.
- 집어서 놓으면 중력으로 바닥까지 떨어진다. 자는 펫은 클릭하면 깬다.
- 메뉴에 `동작 보기 (테스트용)` 추가(잠자기·달리기·벽 타기·혼자 놀기).
- 검증: 타입 검사, 단위 테스트 117건, 스모크 통과. 그림은 이미지로 렌더해 확인했다. 실제 화면 동작(벽 타기 위치, 매달리기, 창이 화면 밖으로 걸칠 때의 모습)은 직접 실행해서 확인해야 한다.
- 알려진 한계: 화면 위쪽 가장자리에서는 말풍선이 화면 밖으로 잘릴 수 있다. 천장 걷기는 없다. 그림은 여전히 임시 도트다.

## 2026-11-24 — 2단계: 놓친 부분 찾기와 배움 카드

- 흐름: 펫이 10초마다 localhost 탭을 검사 → 문제 옆으로 달려가 `!` → 클릭하면 배움 카드 → 확인 +10 경험치, 고쳐서 사라지면 +20.
- 연결 방식: 크롬 원격 디버깅 포트(CDP). 새 의존성 없이 Node 내장 `fetch`/`WebSocket` 만 쓴다. 최신 크롬은 기본 프로필에서 디버그 포트를 못 열어서, `npm run chrome` 이 분리된 별도 프로필로 크롬을 띄운다.
- 안전 원칙(회사 PC): 로컬 주소 탭만 연결(목록에서 걸러 연결조차 안 함), 로컬이 아닌 WebSocket 주소는 거부, 읽은 내용은 PC 밖으로 보내지 않는다. 화면 캡처 + 외부 AI 방식은 쓰지 않았다.
- 검사 규칙 10종: 이미지 alt, 버튼·링크 이름, 입력칸 라벨, html lang, title, viewport, 제목 순서, 누르는 영역 크기, 가로 넘침, 글자 명암 대비. 한 규칙당 한 번에 최대 3개만 알린다.
- 수집기는 페이지 안에서 실행되는 함수 하나(`collectPage`)이고, `toString()` 으로 주입한다. 그래서 밖의 변수를 쓰면 안 되고, 테스트에서 문자열로 실행해 이를 확인한다.
- 보상 규칙: 같은 문제는 `페이지 주소|규칙|요소 경로` 키로 센다. 확인한 문제가 이번 검사에서 사라지고 그 페이지를 검사했다면 "고친 것"으로 보고 한 번만 보상한다. 다른 탭이 닫혀서 안 보이는 것을 고친 것으로 착각하지 않는다.
- 검증: 타입 검사, 단위 테스트 195건 통과. 시험 페이지(`npm run demo`)를 실제 크롬에 열어 검사한 결과 규칙 10종이 모두 잡혔다. 값 없는 submit 버튼은 브라우저 기본 이름이 있어 오탐이라 제외했다.
- 아직 눈으로 확인하지 못한 것: 펫이 요소 옆으로 정확히 가는지(좌표 변환은 확대 100%·테두리 좌우 동일 가정의 근사), 배움 카드 창의 모양, 고침 보상 흐름.
- 다음: 위치 정확도 확인·보정, 배움 카드에 확인 퀴즈(대충 누르기 방지), 검사 규칙 추가, 지식 알림(3단계).

## 2026-11-24 — 확인 퀴즈와 FE 지식 알림(3단계)

- 사용자가 지금은 직접 테스트하기 어려워서, 단위 테스트와 화면 미리보기로 검증할 수 있는 부분을 먼저 만들었다.
- 확인 퀴즈: 규칙마다 한 문제(보기 3개, 해설 포함). 퀴즈를 풀어야 `확인했어요`가 활성화된다. 채점은 렌더러가 아니라 메인 프로세스가 한다(보기 번호만 받아서 정답과 비교하고, 퀴즈를 풀지 않은 확인은 거부). 맞히면 +5 보너스.
- FE 지식 알림: 지식 19개를 앱에 내장(외부 서비스 의존 없음, 오프라인·사내망 OK). 20분마다 가만히 있을 때 펫이 알리고, 누르면 지식 카드가 열린다. 처음 읽은 지식만 +2, 읽은 기록은 progress.json 의 tipsSeen. 처음 계획한 "피드를 검색해서 알려 주기"는 네트워크 의존과 파싱 위험이 있어 보류했다(필요하면 내장 목록에 이어서 붙인다).
- 알림 우선순위: 문제를 알리는 중·카드가 열린 중·이전 지식 대기 중에는 지식을 알리지 않는다.
- 카드 화면을 임시 로컬 서버와 가짜 데이터로 브라우저에 띄워 눈으로 확인했다. 그 과정에서 푸터 버튼이 스크롤해야 보이던 문제를 하단 고정으로, 한글이 단어 중간에서 끊기던 문제를 `word-break: keep-all` 로 고쳤다. 카드 창 높이는 600px.
- 테스트: 223건 통과(카드 화면 8건 포함: 퀴즈 전에는 확인 불가, 정답·오답 표시, 해설, HTML 비해석 등).
- 아직 눈으로 확인하지 못한 것은 이전과 같다(펫이 요소 옆에 정확히 서는지, 실제 Electron 카드 창 위치).

## 2026-11-24 — 플랫폼(웹사이트·계정·수집·거래) 설계 시작

- 요청: gitanimals 처럼 사이트를 만들고, GitHub 로그인으로 사용자 정보를 관리하며, 펫 사고팔기·진화·뽑기를 지원한다. "백엔드 없이 가능한가?"
- 결론: 직접 운영하는 서버 없이 **서버 역할을 하는 서비스(Supabase)** 로 가능하다. 브라우저 코드만으로는 불가능하다(로그인 비밀키, 뽑기 확률 조작, 두 사용자 간 원자적 거래, 재화 위조 때문).
- gitanimals 는 Kotlin 백엔드(약 583KB)와 별도 렌더 서버로 이루어져 있다.
- 설계 문서: [platform-design.md](platform-design.md). 핵심은 "클라이언트는 테이블을 직접 못 쓰고 서버 함수(RPC)만 부른다", 재화는 서버가 양을 정하고 원장(ledger)에 남긴다, 거래는 한 트랜잭션에서 행 잠금으로 처리한다, 재화에 현금성을 두지 않는다.
- 정정: 앞서 "데스크톱은 GitHub Device Flow 로 비밀키 없이 로그인"이라고 했지만, 그 결과(GitHub 토큰)를 Supabase 세션으로 바꾸려면 서버 함수가 따로 필요하다. 서버 코드 없이 되는 표준 방식은 **브라우저 로그인 + 딥링크(PKCE)** 라서 문서는 이쪽으로 정했다.
- 코드 변경은 없다. 열린 질문(레포 구조·이름·공개 범위 등)은 문서 11장에 정리했다.

### 결정: 한 레포에 전부 + DB 구현

- 결정: 프론트엔드·DB/서버 함수·데스크톱 앱을 한 레포에 둔다. 폴더 이동(`apps/`·`packages/`)은 하지 않고 루트는 데스크톱 앱 그대로, `supabase/` 와 `web/` 을 추가하는 방식으로 간다(직접 테스트하기 어려운 시점에 잘 돌던 앱을 건드리는 위험을 피함).
- 구현: `supabase/migrations/` 에 스키마·권한·펫 6종 시드·서버 함수 7개. 테스트는 PGlite(실제 Postgres, Docker 불필요)로 82건.
- 권한 검증: 변조한 마이그레이션(쓰기 권한 개방)을 끼웠을 때 테스트가 정확히 잡는 것을 확인했다.
- 테스트 중 발견: 정합성 테스트가 다른 테스트가 남긴 판매글을 사서 펫 수가 늘어난 것은 서버 버그가 아니라 테스트 가정 문제였다(범위를 해당 사용자들의 글로 한정). 진화 테스트는 임시 종을 지우는 순서(외래 키) 문제였다.
- 알려진 한계: PGlite 는 연결이 하나라 진짜 동시 접속 경쟁을 시험하지 못한다. 행 잠금·고정 잠금 순서로 설계했고, 실제 프로젝트가 생기면 동시 호출 테스트를 추가한다.
- 정정: 설계 초안의 `trade_fee` 원장 항목과 `github_login` 유일 제약은 구현에서 뺐다(이유는 platform-design.md 0장).
- 다음: 사용자가 Supabase 프로젝트·GitHub OAuth App 을 만들면 웹(P1, `web/`)과 데스크톱 로그인(딥링크)을 시작한다. 그 전에는 DB 쪽을 더 다듬거나 데스크톱 앱 쪽 동기화 코드(서버 없이 시험 가능한 부분)를 준비할 수 있다.

### 정정: 지식은 카드 창이 아니라 펫 위 말풍선으로

- 요청: FE 지식은 펫 머리 위 말풍선으로 알려 주고, 거기서 `확인`을 누르면 사라지게 한다(카드 창이 아니다). 위 "지식 카드" 구현은 이 방식으로 교체했다. 카드 창은 문제 알림(배움 카드+퀴즈) 전용으로만 남았다.
- 창을 160x120 에서 460x410 으로 키웠다. 펫이 없는 투명한 부분은 클릭이 통과하므로 방해되지 않는다. 폭은 말풍선(240)에 더해 화면 끝에서 안쪽으로 밀 거리(약 104)를 양쪽에 담도록 잡았고, 테스트로 고정했다.
- 말풍선 안의 버튼을 누를 수 있도록, 펫 위뿐 아니라 말풍선 위에서도 클릭을 받는다(그 밖은 통과).
- 말풍선 높이를 모든 지식에 대해 실제 렌더링으로 쟀다: 기본 150~203px, 코드를 펼치면 최대 325px. 너무 커서 코드 블록은 접어 두고 `코드 보기` 로 펼치게 했다. 높이 기준은 `TIP_BUBBLE.maxHeight`(330).
- 말풍선이 떠 있는 동안 펫은 제자리에 선다. 위쪽 공간이 부족하면 자동 알림을 미루고, 메뉴로 직접 불렀을 땐 펫을 아래로 떨어뜨린다.
- 미리보기로 찾은 버그 2건: (1) CSS 에서 `body` 가 `--shift` 를 자체 선언해 html 에 넣은 값을 덮어써서 옆으로 밀기가 적용되지 않았다. (2) 창 폭이 280 이라 밀린 말풍선이 창 경계에서 잘렸다. 둘 다 고쳤다. 단위 테스트(jsdom)는 속성이 설정됐는지만 봐서 (1)을 잡지 못했고, 실제 렌더링에서 발견했다.
- 테스트 242건 통과(펫 화면 테스트 신규: 말풍선 표시·확인·HTML 비해석·클릭 통과 등).
