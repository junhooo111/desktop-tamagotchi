# 서버 판정 단계 로드맵

> 상태: 계정 로그인과 **계정 저장분 동기화(0004)** 는 끝났다. 이 문서는 그 위에 **서버가 판정하는 기능**(뽑기·거래·도감·랭킹·프로필 카드)을 앱과 연결하는 순서다.
> 기본 설계는 [platform-design.md](platform-design.md). 아래 결정은 기본값이며 바꿀 수 있다.

## 지금 상태와 간극

| | 앱(로컬, v0.9) | 서버 DB(0001~0003) |
|---|---|---|
| 동물 | 일반 14종 + 히든 6종(전설 단계), 꾸미기 장식·색 | 6종(병아리·오리·토끼·고양이·강아지·거북이), 등급 common/rare/epic |
| 재화 | **뽑기권**: 출석 1, 켜 둔 6시간마다 1(하루 1), 돌봄 25회마다 1, 레벨 보상, 선물 상자, 업데이트 선물 2 | **코인**: 학습 이벤트로만 획득, 환영 100, 뽑기 100 |
| 뽑기 | 동물 3장·꾸미기 2장, 히든 1%씩(6%), 40번 천장, 중복이면 경험치 +30 | 100코인, 희귀 이상 천장 10번, 중복 처리 없음 |
| 판정 | 전부 앱이 한다(신뢰) | 전부 서버 함수가 한다 |

그대로는 연결할 수 없다. 서버 규칙을 앱 규칙에 맞춰야 한다(앱을 서버에 맞추면 이미 쓰는 사용자의 경험이 깨진다).

## 결정(기본값)

1. **재화는 둘이다(2026-11-27 사용자 결정으로 변경).** **뽑기권(tickets)** 은 앱의 뽑기권 그대로(환영 3, 동물 3장, 꾸미기 2장, 출석 1)이고 거래하지 않는다. **게임머니(coins)** 는 진짜 게임머니로, 동물 돌봄·업적·**GitHub 커밋**으로 얻어 경매장에서만 쓴다. 원장은 재화별(`currency`)로 "잔액 = 원장 합계".
2. **서버가 판정하는 것은 "희소하거나 거래되는 것"부터**: 뽑기(확률·천장·중복), 동물 소유, 거래, 장착 펫. 뽑기권을 얻는 규칙(출석·켜 둔 시간·돌봄)은 서버가 **하루 상한과 멱등으로 제한**해서 받는다(완벽한 부정 방지는 하지 않는다 — 현금성이 없다는 전제).
3. **기존 사용자의 진행은 잃지 않는다.** 첫 서버 판정 전환 때 계정 저장분(0004)의 컬렉션을 서버 소유 데이터로 **한 번만 가져온다**(`import_local_collection`, 멱등·상한 검사·원장에 `import` 로 기록). 가져온 뒤에는 서버가 기준이다.
4. **거래는 경매장 방식**: 판매자가 가격을 정해 올리고, 다른 사람이 사면 **수수료 없이 가격 그대로** 판매자가 받는다. 거래 재화는 게임머니, 현금화 수단 없음.
5. **랭킹은 서버가 계산한 값만 쓴다**(도감 달성 수, 보유 종 수, 최장 연속 출석). 클라이언트가 보낸 숫자를 그대로 올리지 않는다.
6. **공개 정보는 최소**: GitHub 이름·아바타·장착 펫·도감 수만. 이메일·재화는 비공개.

## 단계

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| **A. 규칙 맞추기 (완료, 0005)** | 종 20개 시드(등급: 일반/히든), 확률(히든 1%씩, 천장 40), 뽑기권 단위 비용(3·2), 중복 경험치 30, 꾸미기 뽑기 | SQL 시험: 확률·천장·중복·비용, 기존 82건을 새 규칙으로 갱신 |
| **B. 가져오기** | `import_local_collection`: 계정 저장분의 컬렉션을 서버 소유 펫·뽑기권으로 한 번 변환 | 같은 사용자 두 번 호출 시 두 번째는 무시, 상한·형식 검사 시험 |
| **C. 앱 연결(뽑기·컬렉션)** | 로그인 상태에서 뽑기·장착은 서버 함수로, 컬렉션 화면은 서버 데이터로. 로그아웃·오프라인은 지금처럼 로컬 | 로그인/오프라인 양쪽 시험, 실패 시 로컬 진행을 건드리지 않음 |
| **D. 도감·랭킹** | 서버 집계 뷰(보유 종 수, 히든 수, 업적 수, 최장 연속). 앱에 랭킹 화면 | 남의 개인 정보가 안 보이는 권한 시험 |
| **E. 프로필 카드(README)** | Edge Function 이 장착 펫을 움직이는 SVG 로 그려 준다(앱의 `renderProfileCard` 재사용). 주소: `…/functions/v1/card?user=<github_login>` | README 에 붙여 GitHub 에서 실제로 보이는지 확인 |
| **F. 경매장** | 앱의 경매장 화면(올리기·취소·구매), 수수료 없음 | 동시 구매·원장 합계 시험(DB 쪽 완료) + 화면 시험 |
| **G. GitHub 커밋 → 게임머니** | gitanimals 방식: 서버(Edge Function)가 GitHub API 로 사용자의 일별 기여(커밋) 수를 읽어, 하루 상한 안에서 게임머니를 준다. 서버 쪽 읽기용 토큰(비밀)이 필요하다(사용자가 Supabase 시크릿으로 직접 등록) | 같은 날 중복 지급 없음, 상한, 토큰이 클라이언트로 새지 않음 시험 |

각 단계는 **마이그레이션 + SQL 시험 + 앱 시험 + 작업 기록**까지 끝내고 커밋하며, 마이그레이션은 `npx supabase db push --linked --yes` 로 적용한다.

## 위험

- **서버 판정으로 옮기는 순간 기존 사용자의 앱 동작이 바뀐다.** 그래서 C 단계는 로그인한 사용자에게만 적용하고, 로그인하지 않으면 지금과 똑같이 로컬로 동작한다.
- 앱 규칙(확률·비용)이 바뀌면 서버 함수와 시드도 같이 바꿔야 한다. 규칙 값은 한 곳(`src/shared/collection.ts`)이 기준이고, 서버 시험이 그 값과 같은지 비교한다.
- 서버가 판정해도 "학습한 척" 이벤트 위조는 못 막는다(상한으로 피해만 제한).
